# Kimball Modeler 0.2.1

**Publicada em 28 de novembro de 2026 · Versão de correção**

Corrige problemas no script de alteração, na exportação e na leitura de scripts em SQL Server, MySQL, Oracle e Snowflake. A atualização é recomendada para quem gera DDL ou compara com o banco fora do PostgreSQL, e não muda nada nos seus arquivos `.dbml`, `.layout.json` ou `.ai.json`.

!!! warning "Erros que aparecem antes do banco"
    Alguns modelos que exportavam antes agora mostram erros na validação: nomes de constraint repetidos, UNIQUE sem a chave de partição, índice único que perderia o filtro e opções com valor inválido. Esses scripts já seriam recusados pelo banco; agora o problema aparece antes, na linha certa e com a correção.

[Baixar a 0.2.1](https://github.com/filipimr/kimball-modeler/releases/tag/v0.2.1){ .md-button .md-button--primary }

## Correções

### Script de alteração (Atualizar o banco e `kimball alter`)

- **Passos falsos fora do PostgreSQL:** num banco SQL Server, MySQL, Oracle ou Snowflake já igual ao modelo, o
  script de alteração trazia dezenas de passos que não mudavam nada. Vários eram destrutivos e recriavam tabelas
  inteiras: tipos que o banco guarda de outro jeito (`datetime` no lugar de `timestamptz`), enums e domínios que o
  banco expande na coluna, defaults, sequences, identidade e atributos de role. Agora a comparação usa o que o banco
  guarda: um banco igual ao modelo dá script vazio em todos os bancos, e as mudanças reais continuam aparecendo.
- **Mudança que o banco não grava:** marcar ALWAYS numa identidade no SQL Server ou no Snowflake recriava a tabela
  inteira; no MySQL, gerava `AUTO_INCREMENT = 1`; trocar uma coluna gerada entre armazenada e virtual num banco que
  só tem uma das duas apagava e recriava a coluna. Agora, se o banco guarda a coluna igual antes e depois, não há
  passo.
- **Domínio no MySQL e no Oracle:** mudar o tipo de um domínio no MySQL tirava o NOT NULL e o DEFAULT das colunas
  que o usam. No Oracle, tirar o NOT NULL do domínio gerava o mesmo comando duas vezes, e o banco recusava o
  segundo. Agora o NOT NULL e o DEFAULT ficam, e cada comando sai uma vez só.
- **Objetos com "Gerar DDL" desligado:** só as tabelas desligadas ficavam fora da comparação. Agora sequences,
  domínios e índices desligados também ficam fora (antes podiam gerar `DROP SEQUENCE` e `DROP INDEX`).
- **Sequence no SQL Server:** mudar o tipo de uma sequence gerava `ALTER SEQUENCE ... AS`, que o SQL Server recusa.
  Agora a sequence é recriada; se um default a usa, o passo explica como fazer à mão.
- **Identidade:** mudar o início, o passo ou o ALWAYS de uma coluna de identidade não gerava nenhum passo. Agora gera.
- **Coluna gerada no Snowflake:** mudar a expressão apagava e recriava a coluna, perdendo os dados, num banco que nem
  tem colunas geradas. Agora o passo aparece como não suportado, com o motivo.
- **Índice sem mudança real:** no MySQL e no Oracle, mudar só uma opção que o banco não escreve (como o filtro do
  índice) recriava um índice idêntico. Agora não recria.
- **Opções da FK:** quando o banco não tem DEFERRABLE ou MATCH, o passo avisa que a opção fica fora do banco, em vez
  de omiti-la sem dizer.
- **Transação:** no PostgreSQL e no SQL Server, o script agora roda numa transação (`BEGIN` ... `COMMIT`); se um
  passo falhar, nada é gravado. `CREATE INDEX CONCURRENTLY` fica depois do `COMMIT`, porque não roda dentro de uma.
  Nos bancos que gravam cada DDL na hora (MySQL, Oracle e Snowflake), o cabeçalho avisa e os passos são numerados,
  para retomar do passo que falhou.
- **Passo sem SQL:** mudar um domínio ou uma partição no Snowflake aparecia como aplicado, com o script vazio. Agora
  aparece como não suportado, com o motivo.

### Exportação de DDL

- **SQL Server:** "Só criar se não existir" e o script de DROP com `IF EXISTS` eram ignorados. Agora o script usa a
  guarda do SQL Server.
- **"DROP antes" num banco vazio:** no SQL Server, no MySQL e no Oracle 19c/21c, o script falhava logo no primeiro
  DROP quando as tabelas ainda não existiam. Agora cada DROP só age se o objeto existir.
- **Índice por expressão no SQL Server:** saía `((lower(email)))`, que o SQL Server recusa. Agora o índice fica fora do
  script, com aviso. No Snowflake, um índice único por expressão virava `UNIQUE ()`; agora fica fora.
- **UNIQUE em coluna que aceita nulo no SQL Server:** o SQL Server aceita um NULL só num UNIQUE, e a carga falhava
  no segundo. Agora sai como índice único filtrado (`WHERE coluna IS NOT NULL`), com uma nota no script.
- **Particionamento:** no MySQL, a FK em tabela particionada (que o banco recusa) fica fora do script, com aviso.
  No MySQL e no Oracle, as partições hash saem com os nomes do modelo.
- **Permissões:** no Oracle, `WITH GRANT OPTION` para role (que o banco recusa) fica fora; no MySQL, a permissão
  para PUBLIC também. No Oracle 19c e 21c, `CREATE ROLE` não falha mais quando a role já existe.
- **Um arquivo por tipo:** roles e permissões ficavam fora dos arquivos. Agora saem em `roles` e `permissoes`, na
  mesma ordem do script único.
- **MySQL:**
  - a partição DEFAULT de uma partição por faixa sumia; agora vira `MAXVALUE`;
  - o início da identidade se perdia; agora sai como `AUTO_INCREMENT=n`, com aviso;
  - um default com sequence gerava SQL inválido; agora fica fora do script, com erro na validação explicando o motivo.
- **Comentários de sequences e domínios:** saíam só no PostgreSQL. Agora saem em todo banco que guarda comentário
  nesses objetos e geram aviso onde o banco não guarda.

### Validação

- **SQL Server:** FKs em cascata que formam um ciclo ou dois caminhos até a mesma tabela agora dão erro, com a
  correção para NO ACTION. Antes, só o banco recusava o script.
- **FK para chave DEFERRABLE:** o erro aparecia em todos os bancos. Agora aparece só onde o banco recusa.
- **Opções de constraint com valor inválido:** `deferrable: initially_deferred`, `match: weird` ou
  `nulls_not_distinct: talvez` sumiam do DDL sem aviso. Agora dão erro na linha, com os valores aceitos.
- **Índices:** índice único que perderia o filtro no banco de destino agora dá erro (sem o filtro, ele recusaria
  dados na carga). Opção de índice de outro banco (`postgres_where`, `postgres_include`) e filtro escrito do jeito
  do PostgreSQL (`where: 'ativo'`, `::`, `||`) agora geram aviso.
- **Particionamento:** UNIQUE sem a chave de partição agora dá erro onde o banco exige (antes só a chave primária
  era conferida). No Oracle, que aceita chave primária global, o erro falso sumiu.
- **Permissões:** CASCADE no REVOKE e `inherit: false` agora avisam onde o banco não tem.
- **Nomes repetidos:** constraints com o mesmo nome agora dão erro conforme cada banco: por tabela no PostgreSQL,
  por schema no Oracle, no MySQL e no SQL Server. No Oracle, tabela e índice com o mesmo nome não são mais erro.
  Sequence, enum ou domínio com o nome de uma tabela também dão erro onde o banco recusa.
- **Partição por faixa no MySQL e no Oracle:** esses bancos só guardam o limite superior de cada faixa. Agora há
  aviso de que valores abaixo da primeira faixa também entram nela.

### Modelo DBML

- **Índice automático da FK:** um modelo com `fk_index` não abria em outras ferramentas DBML (o parser oficial
  recusava o `fk_index` sem aspas e a marca `propagated` no índice). Agora o arquivo passa no parser oficial, e os
  arquivos antigos continuam abrindo.

### Importar SQL

- **SQL Server com "Só criar se não existir":** o script com `IF OBJECT_ID(...) IS NULL CREATE TABLE` não era lido
  ("nenhuma tabela encontrada"). Agora volta como o script comum.
- **Início da identidade no MySQL:** o `AUTO_INCREMENT=n` de um script MySQL agora volta como o início da
  identidade da coluna. Antes ficava preso ao MySQL e se perdia ao exportar para outro banco.
- **Partições:** `PARTITION BY KEY` do MySQL volta como hash, e o `INTERVAL` do Oracle volta com as partições
  listadas, os dois com uma nota. Antes se perdiam em silêncio.
- **Particionamento:** scripts de SQL Server (função e esquema de partição), MySQL e Oracle agora voltam com as
  partições. Antes, o particionamento se perdia na leitura.

## Como atualizar

- **Instalador `.exe`:** o app avisa na próxima abertura e atualiza em um clique.
- **`.msi` ou CLI avulsa:** baixe os arquivos da [release 0.2.1](https://github.com/filipimr/kimball-modeler/releases/tag/v0.2.1) e instale por cima da versão anterior.
