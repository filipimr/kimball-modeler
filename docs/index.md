## O que dá para fazer

<div class="grid cards" markdown>

-   **Modelar no diagrama ou no texto**

    ---

    Tabelas, colunas e relacionamentos com a FK criada sozinha. Cada edição no diagrama reescreve só o trecho afetado do DBML.

    [Tabelas e colunas](guia/tabelas-e-colunas.md)

-   **Validar para o seu banco**

    ---

    Troque o banco de destino e veja na hora o que bloqueia a exportação e onde um tipo perde informação.

    [Validação e correções](guia/validacao.md)

-   **Pedir ajuda ao assistente de IA**

    ---

    Pergunte sobre uma tabela ou peça uma revisão. As mudanças chegam como proposta, e você decide o que entra.

    [Assistente de IA](assistente/index.md)

-   **Comparar e atualizar o banco**

    ---

    Compare o banco de hoje com o modelo e receba o script de alteração, com os passos destrutivos desmarcados.

    [Comparar e atualizar](bancos/comparar-e-atualizar.md)

-   **Automatizar no terminal**

    ---

    O programa `kimball` valida, formata, compara e gera DDL no CI, com as mesmas regras do app.

    [Linha de comando](cli/index.md)

-   **Ligar a IA da sua IDE**

    ---

    Claude Code, Cursor, VS Code com Copilot e outras IDEs editam o modelo por MCP, com 39 ferramentas.

    [IA na IDE (MCP)](mcp/index.md)

## Um modelo, cinco bancos

O mesmo DBML gera o SQL de cada banco. Escolha a aba para ver a diferença:

```dbml title="pedidos.dbml"
Table cliente {
  id integer [pk, increment]
  nome varchar(200) [not null]
}

Table pedido {
  id bigint [pk]
  id_cliente integer [not null]
  criado_em timestamp [default: `now()`]
}

Ref: pedido.id_cliente > cliente.id
```

=== "PostgreSQL"

    ```sql
    -- Destino: PostgreSQL 16
    CREATE TABLE cliente (
        id integer GENERATED BY DEFAULT AS IDENTITY NOT NULL,
        nome varchar(200) NOT NULL,
        CONSTRAINT cliente_pk PRIMARY KEY (id)
    );

    CREATE TABLE pedido (
        id bigint NOT NULL,
        id_cliente integer NOT NULL,
        criado_em timestamp DEFAULT now(),
        CONSTRAINT pedido_pk PRIMARY KEY (id)
    );

    ALTER TABLE pedido ADD CONSTRAINT pedido_id_cliente_fk FOREIGN KEY (id_cliente) REFERENCES cliente (id);
    ```

=== "SQL Server"

    ```sql
    -- Destino: SQL Server 2022
    CREATE TABLE cliente (
        id int IDENTITY(1,1) NOT NULL,
        nome nvarchar(200) NOT NULL,
        CONSTRAINT cliente_pk PRIMARY KEY (id)
    );
    GO

    CREATE TABLE pedido (
        id bigint NOT NULL,
        id_cliente int NOT NULL,
        criado_em datetime2 CONSTRAINT pedido_criado_em_df DEFAULT SYSDATETIMEOFFSET(),
        CONSTRAINT pedido_pk PRIMARY KEY (id)
    );
    GO

    ALTER TABLE pedido ADD CONSTRAINT pedido_id_cliente_fk FOREIGN KEY (id_cliente) REFERENCES cliente (id);
    GO
    ```

=== "Snowflake"

    ```sql
    -- Destino: Snowflake
    CREATE TABLE cliente (
        id INTEGER AUTOINCREMENT NOT NULL,
        nome VARCHAR(200) NOT NULL,
        CONSTRAINT cliente_pk PRIMARY KEY (id)
    );

    CREATE TABLE pedido (
        id BIGINT NOT NULL,
        id_cliente INTEGER NOT NULL,
        criado_em TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP(),
        CONSTRAINT pedido_pk PRIMARY KEY (id)
    );

    ALTER TABLE pedido ADD CONSTRAINT pedido_id_cliente_fk FOREIGN KEY (id_cliente) REFERENCES cliente (id);
    ```

=== "MySQL"

    ```sql
    -- Destino: MySQL 8.4
    CREATE TABLE cliente (
        id int AUTO_INCREMENT NOT NULL,
        nome varchar(200) NOT NULL,
        CONSTRAINT cliente_pk PRIMARY KEY (id)
    );

    CREATE TABLE pedido (
        id bigint NOT NULL,
        id_cliente int NOT NULL,
        criado_em datetime DEFAULT CURRENT_TIMESTAMP,
        CONSTRAINT pedido_pk PRIMARY KEY (id)
    );

    ALTER TABLE pedido ADD CONSTRAINT pedido_id_cliente_fk FOREIGN KEY (id_cliente) REFERENCES cliente (id);
    ```

=== "Oracle"

    ```sql
    -- Destino: Oracle 23ai
    CREATE TABLE cliente (
        id NUMBER(10) GENERATED BY DEFAULT AS IDENTITY NOT NULL,
        nome VARCHAR2(200 CHAR) NOT NULL,
        CONSTRAINT cliente_pk PRIMARY KEY (id)
    );

    CREATE TABLE pedido (
        id NUMBER(19) NOT NULL,
        id_cliente NUMBER(10) NOT NULL,
        criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
        CONSTRAINT pedido_pk PRIMARY KEY (id)
    );

    ALTER TABLE pedido ADD CONSTRAINT pedido_id_cliente_fk FOREIGN KEY (id_cliente) REFERENCES cliente (id);
    ```

A pílula do banco, no topo do app, troca o destino. A página [Bancos de dados](bancos/index.md) mostra as versões suportadas e o que muda em cada um, e [Converter para outro banco](bancos/conversao.md) explica o relatório de perdas.
