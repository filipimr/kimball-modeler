Mude o banco sem medo do ALTER

Compare o banco de hoje com o modelo e receba o script pronto. O que é seguro já vem marcado. DROP e recriação de tabela esperam você ler o SQL e decidir.

Feito para quem vive no terminal

O motor do app também roda na linha de comando. Ponha o modelo no pipeline e deixe o CI barrar o que não passa.

# no pipeline, a cada pull request $ kimball fmt modelo.dbml --check $ kimball validate modelo.dbml --dialect sqlserver --json $ kimball diff main.dbml modelo.dbml --dialect sqlserver $ kimball export modelo.dbml --dialect sqlserver -o ddl.sql

Dúvidas de quem está chegando

Preciso saber DBML para usar?

Não. Dá para fazer tudo no diagrama, e o DBML é escrito para você. Quem prefere código edita o texto direto, com autocompletar e checagem de erro.

Funciona com o meu banco?

O Kimball gera e valida DDL para PostgreSQL (12 a 18), SQL Server (2016 a 2025), Snowflake, MySQL (8.0 a 9.0) e Oracle (19c a 23ai), com as regras da versão que você escolher. A conexão direta com o banco, por enquanto, é só com PostgreSQL.

Consigo trazer o banco que eu já tenho?

Sim. Importe scripts SQL ou DDL (vários de uma vez), um Modelo Físico XML (.pdm) com as posições do diagrama, ou uma planilha .xlsx, .ods ou .csv com tabelas e colunas. No PostgreSQL, dá para conectar e ler o schema direto.

A IA vê os meus dados?

Não. O assistente recebe só a estrutura do modelo: tabelas, colunas, tipos e relações. Você escolhe o provedor e pode usar um modelo local com Ollama, sem nada sair da sua máquina.

Onde o meu modelo fica salvo?

Na sua máquina, em dois arquivos: o .dbml com o modelo e o .layout.json com as posições do diagrama. Versione os dois no Git.

O script de alteração pode apagar dados?

Só se você mandar. Todo DROP e toda recriação de tabela aparecem destacados e desmarcados, e você vê o SQL antes de incluir. Para rodar direto no banco, o app lista cada passo destrutivo e pede confirmação.

Encontrei um problema. Como aviso?

Abra uma issue no GitHub com o passo a passo e, se puder, um trecho do modelo. Sugestões também são bem-vindas por lá. Para outros assuntos, escreva para filipimr@outlook.com.
